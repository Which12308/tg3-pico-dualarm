# 按完整 prompt 验收的操作契约

本项目以头部和左右控制器的有效位姿，将双手相对位置及朝向重定向到机器人，用实际 URDF／Placo 求解双臂。头显与两个手柄不直接测量人体肩肘，不能唯一复制人体全关节姿态。左右控制器是手部定位器，按钮决定跟随与抓放；不调用旧右臂遥控、A/B 抓瓶预姿态、瓶型数组或遥控器通道模拟。

## 从连接到启用

| 用户动作／情况 | 本项目行为 |
|---|---|
| USB 连接／首次安装原生 APK | 校验唯一已授权 PICO、ARM64／API 并安装；启动接收或安装后自动设置 ADB reverse，默认保持数据线，不用 USB 网络共享 |
| 原生配对页默认 USB，填写配对码；Wi-Fi 可选 | USB 地址固定 `127.0.0.1`，只有 Wi-Fi 才填电脑 IP；表单期间不发送 VR 动作；点击“配对并进入透视采集”后进入 OpenXR 采集，无第二次开始按钮 |
| 左菜单键 | 停止采集输入，返回配对页；不继续使用旧目标 |
| 默认部署启动 | `dry_run`，运行真实双臂求解、模型预览和录制，不发送物理命令 |
| 加载已审查厂家 JSON | 校验指定驱动源码、哈希、来源和限制；加载本身不授权运动 |
| 选择 `hardware` 并启动 | 建立独立厂家会话，保持未使能；没有有效 provider 或真实反馈时拒绝动作 |
| 点击“启用真机运动” | 检查新鲜输入、双手松开、透视、工具标定、实际反馈、物理急停和控制器状态，再请求控制权 |
| 请求已入队／已接受 | 仍等待厂家实际 ACK；不能显示为硬件已启用 |
| 收到实际新鲜控制权确认 | 创建本项目运动发布者，用实际关节反馈重建参考；之后才接收操作动作 |
| 全局断线、换会话、停用或故障后恢复 | 不自动启用；双手松开并重新显式申请，等待新 ACK |

具体本机厂家 provider 尚待核实；通用 ROS 发布器、反馈适配、控制权会话和上述准入链已经实现。现场需完成工具和手部标定以及厂家与物理动作验收，当前版本未标记“真机可用”。

## 双臂与抓放

| 用户动作／情况 | 本项目行为 |
|---|---|
| 左握持键按住后移动／旋转 | 左手部目标跟随左控制器；不把它的位移映射给右手 |
| 右握持键按住后移动／旋转 | 右手部目标跟随右控制器；不把它的位移映射给左手 |
| 两侧均握持 | 双侧独立目标进入同一个双臂求解器和输出边界 |
| 松开一侧握持键 | 该侧退出主动跟随并保持；另一侧在全局有效时可继续 |
| 手柄换到舒适位置后重新握持 | 重建局部参考，不跳回上次握持起点 |
| `position` 模式 | 只跟随手部位置，转腕不改变目标朝向 |
| `pose` 模式 | 同时跟随位置和朝向；默认平移与旋转均 1:1 |
| 伸手、抬手、侧移、转腕 | 将对应手部操作点的相对运动交给 IK；肩肘如何转动受机器人模型与姿态参考决定 |
| 加速、减速、反向或不可达目标 | 遵守配置速度、加速度、工作空间和反馈领先；没有可行安全增量时拒绝输出 |
| 按扳机 | 按限速渐闭；较小闭合请求不会主动张手 |
| 松开扳机 | 立即取消尚未完成的继续闭合，保留已达到的握持 |
| 左 Y／右 B | 分别请求左／右手张开，优先于扳机；需释放扳机后才可再闭合 |
| A／X 与摇杆 | 仅作原始输入记录，不绑定旧抓瓶手型或关节动作 |
| 单手跟踪失效或数据陈旧 | 该侧不再使用旧目标，取消未完成闭合且不自动松物；恢复后需新鲜松开再握持 |
| 头部失跟踪、应用暂停／失焦、重定位或全局会话失效 | 撤销坐标参考和旧目标；硬件会话停用后还需电脑重新显式启用 |
| 走动观察 | 先松开双侧握持，避免把行走位移发给机器人；恢复需按当前状态重新接管 |

手部硬件输出从新鲜六通道反馈初始化，分别采用左右厂家实测端点、速度、电流和原始变化限制。闭合量只是标定投影估计，不能把电流当作直接测得的夹持力或触觉。输入失效时冻结握持不等于物理防滑保证。

## 坐标、标定与反馈

原生 OpenXR 输入已是右手坐标 X 右、Y 上、Z 后，位置为米、四元数 XYZW，声明 `openxr_rh_y_up`。不再做 Unity 左手坐标反射；各输入源按自己的坐标声明校验。头部水平朝向用于建立操作方向。

工具标定由 `controller_to_hand`（控制器握持坐标到人体操作点）和 `tcp_to_hand`（机器人 URDF TCP 到实际掌心／抓握点）组成，左右分别配置 SE(3)。握持时以操作点建参考，转腕后换算回机器人 TCP。默认单位变换明确标为未实测；必须真实测量、保存依据后才可申请真机运动。

“URDF 模型预览”显示求解目标与模型状态，不能冒充真实电机反馈；真实反馈与硬件提交结果另行标注。没有实际反馈就保留缺失，不填入模型值。所有启动、重连和重定位均不自动重用旧控制参考，跨设备时效按传输上界累计，不相减两台设备的单调时钟。

软件限幅、厂家保持／停止恢复与物理急停是不同机制；当前模型没有完整碰撞网格，也不提供硬实时保证。各分支物理效果必须通过现场验收。完整输入、目标、动作和失效均可录制，D455 图像通过真实 ROS 话题另录，时间对齐仍需现场校核。
