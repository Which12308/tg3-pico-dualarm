# 系统实现

0.4.0 默认入口为原生 OpenXR：`headset_native/` APK → USB 的 ADB reverse → `wireless.py` Windows 接收器 → 经 SSH 的最新帧转发 → `station.py` 原生 IK／诊断／录制。Wi-Fi 为可选头显连接方式。`desktop/` 负责配对、独立依赖、部署与状态。APK 已实际构建、安装并收到物理 PICO 输入；Linux 原生求解与 ROS 构建也已执行，具体版本、源码快照和现场未验项目见验证回执。

输入层 `tracking.py` 和 `web_input.py` 提供头部、左右手柄的带时戳位姿，包含实际连接与跟踪状态、按键和独立释放门控。WebXR 用真实 XR 帧采样，服务端通过一次性时限挑战和接收时钟控制延迟。原生 XRoboToolkit 绑定接入类保留逐手柄有效性缺失的限制，不用不存在的置信度伪装已验证跟踪。

`mapping.py` 将头部水平朝向标定为机器人前伸方向，左右手独立记录握持参考。相对平移与 SE(3) 朝向运算支持比例调整；新跟踪会话重做朝向标定。当前目标点是模型定义的 TCP；真实手柄到掌心/抓握中心的固定偏置尚未测量。

`kinematics.py` 直接使用成熟 Placo 原生求解器，载入来自实际机器人、哈希校验的 URDF，固定腰部与基座，仅包含双臂14个关节。双侧位置/完整位姿任务和低权重握持姿态参考共同求解；未接管侧输出保持原目标。人体肩肘不是被直接观测的输入。

`safety.py` 在求解结果之后限制关节速度、加速度、软限位、反馈领先，以及实际模型末端的平移/旋转增量；每次握持以参考点为中心限制相对工作空间。看门狗独立线程能关闭 DryRunRobot 接口，原生求解卡住时不会继续提交离线命令，但不代表硬件实时安全回路或可中断的 QP 调用。

`robot.py` 定义机器人边界。`manufacturer.py` 实现单条十四关节 ROS 输出、独立手部输出、反馈校验与厂家控制契约；`manufacturer_session.py` 管理真实 ROS 会话，`motion_control.py` 等待操作者使能和厂家确认。缺少经审查的本机厂家 provider 时，在运动发布者创建前拒绝硬件启动。`manufacturer_grasp.py` 从六通道实测位置执行连续抓放，保留厂家限速与反馈窗口，不把电机停滞当成接触或抓稳的证明。`preflight.py` 读取实际状态与发布者；`ros_bridge.py` 的模型验证只发布显式标记的标准诊断和关节状态，不发布 `/arm/cmd`。

`recording.py` 保存输入、标定、目标、实测/离线状态和实际提交指令，记录解除接管原因。ROS 相机与机器人话题由独立现成 rosbag2 录制器保存。两类文件没有自动完成跨电脑时钟同步；采集时必须明确时钟域和对齐方式。

这是一条实际可运行的输入→标定→原生IK→限幅→离线指令链。对天工双臂的硬件发布仍取决于已确认的原厂授权路径、模式仲裁和现场验证；尚未实现完整碰撞约束，不称为生产验收完成。
